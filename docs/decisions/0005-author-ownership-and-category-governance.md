# 0005：作者归属和分类治理

## 状态

已接受。

## 背景

普通用户开始拥有上传和维护小说的能力后，作者不能继续作为自由文本写入，否则会出现冒名、权限无法判断和分类不可控的问题。

## 决策

- `users.username` 作为小说作者展示的系统引用名，昵称不影响作者名。
- `books.owner_user_id` 作为真实作者归属和权限判断来源。
- 管理员创建或上传的小说展示作者为“系统”。
- 旧 `books.author` 字段保留兼容期，用于历史数据迁移和回退。
- 普通用户只能管理 `owner_user_id` 等于自己的小说和章节。
- 管理员可以管理所有小说和章节。
- 小说创建、上传和编辑只接受已有 `categoryId`。
- 分类新增、重命名和删除仅管理员可操作。
- 已被书籍使用的分类不允许删除。

## 影响

- 后端查询书籍时需要关联 `users` 计算 `author`。
- 前端小说表单使用分类下拉，不再使用自由输入。
- smoke 需要覆盖普通用户作品权限、分类约束和搜索空结果。
