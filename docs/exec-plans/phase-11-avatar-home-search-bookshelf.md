# Phase 11：用户头像、首页合并搜索分页与我的书架

## 状态

已完成并通过验收。

## 任务类型

- 新需求
- UI 调整
- API/数据契约变化
- 数据库迁移
- 测试补强
- Harness 更新

## 背景

当前系统已经具备前台登录、小说搜索、书籍详情、章节阅读、作者端和后台端能力，但仍有三个明显缺口：

1. 前台用户资料没有头像能力。
2. 书库页和发现页仍然分离，搜索结果页 `/search` 还是独立页面。
3. 用户缺少一个明确的个人书架页，无法集中查看自己加入书架的书籍。

这三个需求都属于前台用户体验的连续增强，适合一起进入同一轮契约调整：

- 头像属于前台账号资料能力。
- 首页合并搜索结果属于读者端信息架构调整。
- 书架页属于前台用户的个人藏书关系管理。

## 目标

1. 让前台用户可以上传并维护头像。
2. 取消独立的 `/search` 页面，把书库搜索结果并入首页/发现页。
3. 首页搜索结果支持分页，并允许用户选择每页数量 `10`、`20`、`50` 或自定义。
4. 新增“我的书架”页面，展示当前用户加入书架的书籍。
5. 为后续浏览器端体验和数据契约迭代留下清晰边界。

## 非目标

- 不新增评论、关注、推荐算法、私信或社交关系。
- 不做头像社交化组件，例如好友头像墙、头像挂件或头像框商城。
- 不做书架分组、书架标签、批量导出或多层级收藏夹。
- 不把首页改造成复杂的运营后台。
- 不复制任何第三方阅读站的品牌资产、精确布局或专有文案。

## 默认实现假设

- 头像采用本地文件存储，和封面图、站点图标一样由服务端生成路径。
- 头像上传入口放在前台账号页，上传成功后可在账号页和全站用户展示区同步显示。
- `书架` 视为前台用户与书籍之间的一种个人关系，不等同于书籍内容本身。
- 书架支持分组、置顶和批量管理。
- 首页继续承担“发现 + 搜索”的合并入口，`/search` 不再作为独立内容页暴露在导航里。
- 旧的 `/search` 地址在实现时可保留为重定向或兼容跳转，避免外链和浏览器历史突然失效；是否彻底下线可在确认阶段再定。
- `我的书架` 只对已登录前台用户开放，读者和作者都可以使用。

## 需求理解校准

### 术语净化映射

- `上传头像` -> 前台用户头像文件上传与展示
- `书库页面跟发现页面合并为首页` -> 发现页承载首页信息流与搜索结果
- `取消 /search 页面` -> 取消独立搜索路由，搜索结果内嵌到首页
- `每页页数 10、20、50 或自定义` -> 首页搜索结果分页大小可切换
- `我的书架` -> 当前登录前台用户的个人书籍收藏列表
- `加入书架` -> 用户与书籍之间的个人关系创建
- `移出书架` -> 用户与书籍之间的个人关系删除
- `分组` -> 用户自定义书架分区
- `置顶` -> 在某个分组内提升书籍排序优先级
- `批量管理` -> 对多本书执行移动、置顶、取消置顶或移除操作

### 核心对象与关系

`FrontUserAccount`

- 本质：`identity` 域聚合根。
- 变化点：新增头像引用字段，保存用户头像的服务端相对路径或可渲染 URL。
- 不变量：
  - 头像路径必须由服务端生成。
  - 用户资料变更不能破坏用户名唯一性和现有角色流转。

`ShelfItem`

- 本质：用户与书籍之间的个人关系记录。
- 建议归属：优先作为独立 `shelf` / `library` 子域或 `identity` 的个人藏书子域处理，不建议并入 `book` 内容域。
- 生命周期：加入书架 -> 保留在书架 -> 从书架移除。
- 不变量：
  - 同一用户对同一本书只能有一条有效书架关系。
  - 加入和移除必须对当前登录用户生效，不能操作他人书架。

`ShelfGroup`

- 本质：用户自定义书架分区。
- 生命周期：创建 -> 重命名 -> 调整顺序 -> 删除或保留。
- 不变量：
  - 默认分组始终存在。
  - 默认分组不允许删除。
  - 分组名称在同一用户内应保持唯一，避免导航混乱。

`HomepageSearchSession`

- 本质：前端路由状态和查询条件派生对象，不建议单独持久化。
- 规则：
  - 首页承载搜索条件、分页页码和分页大小。
  - 页面刷新后应能通过 URL 复原当前搜索状态。

## 流程走查（含异常与并发）

### 上传头像

- 前置条件：用户已登录前台账号。
- 触发主体：前台用户。
- 主流程：选择图片 -> 上传 -> 服务端校验 -> 保存文件 -> 更新用户头像引用 -> 前台刷新头像展示。
- 异常分支：
  - 未登录：拒绝并引导登录。
  - 文件类型不合法：返回明确错误。
  - 文件过大：返回明确错误。
  - 上传失败但资料未受影响：保留旧头像，不清空用户资料。
- 并发场景：
  - 连续多次上传时，最后一次成功的头像引用生效。

### 首页搜索与分页

- 前置条件：用户访问首页。
- 触发主体：游客或前台用户。
- 主流程：输入关键词/分类 -> 首页直接展示搜索结果 -> 用户切换页码或页大小 -> URL 与结果同步变化。
- 异常分支：
  - 搜索无结果：稳定展示空状态。
  - 页码越界：回落到可用页或提示重新搜索。
  - 自定义页大小非法：返回校验错误或回退到安全默认值，具体策略待确认。
- 并发场景：
  - 连续快速切换页码时，以最后一次请求结果为准，避免旧结果覆盖新结果。

### 加入书架 / 移出书架 / 分组与批量管理

- 前置条件：用户已登录前台账号。
- 触发主体：前台用户。
- 主流程：在详情页或列表页加入书架 -> 进入默认分组 -> 书架页可见 -> 用户可移动分组、置顶或批量处理。
- 异常分支：
  - 未登录：跳转登录。
  - 重复加入：幂等成功或提示已在书架中，需统一规则。
  - 移除不存在的关系：幂等成功或提示已移除，需统一规则。
- 并发场景：
  - 双击加入书架只能落一条关系记录。
  - 同一书籍在不同页面被同时加入/移除时，最终状态以最后一次成功写入为准。
  - 批量操作与单项操作同时发生时，服务端需要保证每本书的最终状态一致，不出现部分更新不透明的情况。

## 影响范围

- 产品：前台账号资料、首页信息架构和个人藏书能力都要重新定义。
- UI：账号页新增头像上传与预览；首页增加结果分页和页大小选择；导航新增“我的书架”；新增书架页。
- 前端：需要调整路由、导航、首页状态管理、账号页、详情页和书架页。
- 后端：需要新增头像更新接口、书架关系查询和维护接口，以及首页搜索分页契约的明确化。
- API：需要把搜索分页大小、头像上传、书架列表与书架关系维护写入契约。
- 数据库：需要给用户表增加头像引用字段，并新增书架分组和书架关系表。
- 测试：需要补充上传校验、分页边界、书架幂等和权限回归。
- 安全/权限：头像和书架都必须绑定当前前台账号，不能越权访问他人数据。

## 契约变化

### DDD 影响评估

- 领域归属：
  - 头像更新属于 `identity` 域的账号资料能力。
  - 书架关系更像前台用户的个人藏书子域，建议独立建模，不要塞进 `book` 内容域。
  - 首页搜索分页属于 `book` 域的查询能力，但分页大小和路由状态主要落在前端。
- 分层落点：
  - `interface`：承接头像上传、书架列表、加入/移除书架、首页搜索分页等 HTTP 输入输出。
  - `application`：编排头像更新、书架增删、书架列表查询、搜索分页参数归一化。
  - `domain`：定义用户头像引用不变量、书架关系唯一性、幂等操作语义与领域错误。
  - `infrastructure`：实现头像文件存储、书架关系表、用户表字段扩展和必要索引。
- 仓储契约：
  - `identity` 需要新增用户头像更新相关仓储能力。
  - 新的 `shelf` / `library` 领域需要新增用户-书籍关系仓储契约。
  - `book` 查询仓储需要明确支持可变 `pageSize` 的分页查询。
- 决策记录：
  - 如果确认书架要做成独立子域，建议补一条决策记录，固定 `shelf` / `library` 的领域归属和幂等语义。

### API

建议新增或调整：

- `POST /api/auth/me/avatar`
  - 用途：上传或替换当前前台用户头像。
  - 格式：`multipart/form-data`
  - 权限：前台登录。

- `GET /api/auth/me`
  - 调整：增加头像字段，例如 `avatarUrl` 或等价安全渲染字段。

- `GET /api/books/search`
  - 调整：明确支持 `page` 和 `pageSize`，并让前端可传入 `10`、`20`、`50` 或自定义值。

- `GET /api/me/bookshelf`
  - 用途：返回当前用户书架中的书籍列表。
  - 权限：前台登录。
  - 建议支持分页，避免书架过大时一次性返回。

- `GET /api/me/bookshelf/groups`
  - 用途：返回当前用户的书架分组列表。
  - 权限：前台登录。

- `POST /api/me/bookshelf/groups`
  - 用途：创建新的书架分组。
  - 权限：前台登录。

- `PATCH /api/me/bookshelf/groups/{groupId}`
  - 用途：重命名或调整分组顺序。
  - 权限：前台登录。

- `DELETE /api/me/bookshelf/groups/{groupId}`
  - 用途：删除分组。
  - 权限：前台登录。
  - 约束：默认分组不可删除。

- `POST /api/me/bookshelf/{bookId}`
  - 用途：加入书架。
  - 权限：前台登录。
  - 语义：幂等或可重复调用，需在确认阶段统一。
  - 建议支持可选 `groupId`，默认进入默认分组。

- `DELETE /api/me/bookshelf/{bookId}`
  - 用途：移出书架。
  - 权限：前台登录。

- `PATCH /api/me/bookshelf/{bookId}`
  - 用途：移动分组或更新置顶状态。
  - 权限：前台登录。

- `POST /api/me/bookshelf/batch`
  - 用途：批量移动、置顶、取消置顶或移除书架条目。
  - 权限：前台登录。

### 数据

建议新增或调整：

- `users`
  - 新增头像字段，例如 `avatar_path`。

- `shelf_items` 或 `user_bookshelves`
  - `id`：主键。
  - `user_id`：前台用户 ID。
  - `book_id`：书籍 ID。
  - `group_id`：分组 ID。
  - `is_pinned`：是否置顶。
  - `pinned_at`：置顶时间。
  - `created_at`：加入时间。

- `shelf_groups` 或 `user_bookshelf_groups`
  - `id`：主键。
  - `user_id`：前台用户 ID。
  - `name`：分组名称。
  - `sort_order`：展示顺序。
  - `is_default`：是否默认分组。
  - `created_at` / `updated_at`：时间戳。

约束建议：

- 同一用户同一本书只能存在一条有效书架记录。
- 同一用户的分组名称应唯一。
- 头像路径和书架关系都必须由服务端控制，不接受客户端写入任意路径。

### UI 状态

前台账号页：

- 初始态：展示当前头像、昵称和账号信息。
- 上传中：展示进度或加载态。
- 上传成功：即时刷新头像预览。
- 上传失败：保留原头像，不清空表单。

首页：

- 默认态：继续展示发现内容。
- 搜索结果态：展示分页结果和页大小切换。
- 空结果态：稳定展示空状态。
- 自定义页大小态：明确显示当前页大小并可修改。

书架页：

- 加载态：展示正在加载书架。
- 空态：提示尚未加入任何书籍。
- 列表态：展示书籍卡片、移除操作和分页。
- 分组态：展示用户自定义分组、当前分组切换和分组管理入口。
- 置顶态：展示已置顶书籍的视觉优先级。
- 批量态：支持选择多本书后执行移动、置顶、取消置顶和移除。
- 错误态：保留当前筛选条件，允许重试。

## 验收标准

- 前台用户可以上传头像，刷新后头像仍然可见。
- 首页不再依赖独立 `/search` 页面来承载搜索结果。
- 首页搜索结果支持分页，并可切换每页 `10`、`20`、`50` 或自定义页大小，且自定义范围限制为 `1-100`。
- 用户可以把书加入书架，并在“我的书架”页面看到它。
- 用户可以从书架中移除书籍，页面状态同步更新。
- 用户可以创建、重命名、删除书架分组，并将书籍在分组间移动。
- 用户可以将书架中的书籍置顶，并对多本书执行批量操作。
- 未登录用户不能操作头像和书架。
- 搜索无结果、书架为空、头像上传失败时都要稳定展示可理解的 UI。
