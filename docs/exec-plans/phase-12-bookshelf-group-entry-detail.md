# Phase 12：书架分组入口化与分组详情页

## 状态

已确认，待实现。

## 任务类型

- 新需求
- UI 调整
- API/路由调整
- 测试补强
- Harness 更新

## 背景

当前书架页已经支持分组、置顶和批量管理，但分组的呈现方式仍然偏“控制面板”式：

- 分组集中在左侧或顶部作为筛选/管理控件。
- 用户进入书架后，视觉上主要看到的是书籍列表。
- 分组本身没有被当作一等入口页来展示。

用户已确认的新口径：

- 不存在“默认分组”概念。
- 书架本身是书籍容器，分组只是把部分书籍折叠成一个同级入口卡片。
- 分组与书籍在书架首页同级展示。
- 书架首页不提供显式“新建分组”按钮。
- 分组创建与管理从“选中书籍后移动”流程进入，目标是淡化分组概念。
- 点击分组卡片后进入独立路由的分组详情页。
- 分组详情页保留置顶、移动、批量管理能力。

这意味着分组从“辅助筛选控件”升级为“可导航内容入口”。

## 目标

1. 让书架首页的分组以卡片化形式展示，占据和书籍相同的网格位置。
2. 点击分组卡片后进入分组详情页。
3. 分组详情页展示该分组下的书籍，并保留必要的管理动作。
4. 保持现有书架的分组、置顶、批量管理能力不回退。

## 非目标

- 不改为社交书架或公有书单。
- 不新增推荐算法或分组自动整理。
- 不做跨用户共享分组。
- 不复制番茄小说的品牌、视觉资产或精确布局。

## 默认实现假设

- 书架首页展示两类同级卡片：未分组书籍卡片、分组入口卡片。
- 被放入分组的书籍不再在书架首页单独展示，而是在对应分组详情页中展示。
- 分组卡片点击后使用单独路由进入分组详情页，例如 `/bookshelf/groups/:groupId`。
- 分组详情页优先复用现有书架条目接口，不优先新增冗余表结构。
- 分组创建入口放在批量移动弹层或批量操作区域，不在书架首页首屏单独提供“新建分组”按钮。

## 需求理解校准

### 术语净化映射

- `分组在 UI 上也是占一个书籍的位置` -> 分组作为书架首页网格中的独立卡片
- `点击进去是一个新的页面` -> 分组详情路由与分组内容页
- `展示分组里面的数据` -> 展示该分组下的书籍列表与分组状态信息

### 核心对象与关系

`BookshelfGroup`

- 本质：用户对部分书籍的轻量折叠容器。
- 变化点：从管理对象升级为导航对象，但不升级为书架的主心智。
- 表现规则：
  - 在书架首页以与书籍同级的入口卡片展示。
  - 卡片可展示名称、数量、最近一本书封面或摘要。
  - 仅当至少有书被移动进分组后，这个分组才有存在感。

`BookshelfGroupDetail`

- 本质：分组详情页的前端视图模型，不一定需要持久化。
- 需要承载：
  - 分组名称和状态。
  - 分组内书籍列表。
  - 管理动作入口。

## 流程走查（含异常与并发）

### 进入书架首页

- 主流程：加载未分组书籍与分组卡片 -> 以统一网格展示 -> 用户可点击某本书直接阅读，也可点击某个分组进入详情页。
- 异常分支：
  - 没有分组：仍然展示未分组书籍或空状态，不应白屏。
  - 没有未分组书籍但有分组：分组卡片仍应可见。

### 打开分组详情页

- 主流程：进入 `/bookshelf/groups/:groupId` -> 加载该分组信息和该组内书籍 -> 展示分组内容。
- 异常分支：
  - 分组不存在：提示已删除或无权限。
  - 分组为空：稳定展示空状态。
  - 当前组被删除后仍停留在详情页：应回退到书架首页。

### 在分组详情页管理书籍

- 主流程：在详情页内继续支持置顶、取消置顶、移动分组或批量管理。
- 异常分支：
  - 目标分组不存在或不允许移动：返回明确错误。
  - 批量操作中部分条目失败：需要定义是整体失败还是部分成功。

## 影响范围

- 产品：书架从“列表页”升级为“带分组入口的个人藏书空间”。
- UI：书架首页要重构为卡片化网格，新增分组详情页。
- 前端：需要新增或调整路由、书架页面布局、分组卡片组件、详情页状态和导航返回路径。
- 后端：需要去掉默认分组语义，允许书架条目不属于任何分组；如前端无法完整复用现有接口，再新增分组详情数据接口。
- API：需要明确分组详情页是否复用 `groupId` 查询参数还是新增独立路由数据接口。
- 测试：需要补充分组卡片点击、分组详情页、空状态和删除分组后的回退逻辑。
- 安全/权限：分组详情页只能查看当前登录用户自己的分组。

## 契约变化

### DDD 影响评估

- 领域归属：
  - 仍归属书架子域，不建议并入 `book` 内容域。
  - 这次变化除了展示和路由升级，还涉及“条目可不属于分组”的建模变化。
- 分层落点：
  - `interface`：承接书架首页与分组详情页的 HTTP 输入输出。
  - `application`：编排分组卡片展示、分组详情查询、分页与批量操作。
  - `domain`：维持分组唯一性、默认分组不删除、条目归属不越权。
  - `infrastructure`：如需新增接口，只补充最小查询能力。
- 仓储契约：
  - 需要支持“未分组书籍列表”和“分组内书籍列表”两类查询。
  - 如果需要分组详情专用聚合输出，再补仓储/查询方法。

### API

采用以下最小方案：

- `GET /api/me/bookshelf/groups`
  - 用途：返回当前用户分组列表，用于书架首页的分组卡片。
  - 语义：仅返回用户创建过且当前仍存在的分组，不存在默认分组。

- `GET /api/me/bookshelf/groups/{groupId}`
  - 用途：返回当前分组详情与该组内书籍列表。
  - 说明：如果现有 `groupId` 查询参数能满足，也可以只在前端改路由，不新增该接口。

- `GET /api/me/bookshelf?groupId=...`
  - 用途：继续作为分组详情页的书籍分页数据源。

- `GET /api/me/bookshelf`
  - 语义：不带 `groupId` 时仅返回未分组书籍，不再隐含“默认分组”。

## UI 草案

### 书架首页

- 分组和未分组书籍统一放在同一网格中。
- 分组卡片需要像书籍卡片一样占位。
- 分组卡片可以显示名称、数量和封面拼贴或最近书籍摘要。
- 首页不提供独立的新建分组按钮。
- 点击分组卡片进入分组详情页。

### 分组详情页

- 展示分组名称、书籍总数和返回入口。
- 展示该分组内的书籍列表。
- 支持空状态。
- 保留置顶、移动、批量处理。

## 验收标准

- 书架首页能看到分组卡片，且分组卡片占据和书籍一致的卡片位置。
- 点击分组卡片能进入分组详情页。
- 分组详情页能展示该分组下的书籍。
- 无分组、空分组、已删除分组都能稳定处理。
- 现有书架的分组、置顶和批量管理能力不回退。
