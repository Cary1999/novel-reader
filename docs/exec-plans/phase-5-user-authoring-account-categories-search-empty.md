## 背景

当前系统已经支持管理员上传、编辑和删除小说，但普通用户还不能作为作者上传或维护自己的小说；小说作者目前是可写入的字符串，不满足“作者必须是系统内用户名并通过引用获得”的约束；书籍分类在小说表单里仍可自由输入并创建分类，缺少管理员统一治理；账号资料只支持注册和登录，不支持修改密码或设置昵称。

同时，搜索页在无匹配结果时出现页面异常无渲染，需要将该类空结果行为固化为可测试的 UI 状态。

用户已确认草案，当前阶段已完成代码实现。

## 目标

1. 管理页面支持新建小说，不依赖 `.txt` 上传也能创建空小说，再通过章节管理补充内容。
2. 用户支持修改密码和设置昵称；注册时昵称默认等于用户名。
3. 普通用户可以上传小说、创建小说、编辑自己的小说、维护自己的章节。
4. 小说作者名称必须来源于系统用户引用：普通用户作品展示作者为该用户的 `username`；管理员账号上传或创建的小说展示作者为“系统”。
5. 除管理员外，小说和章节的编辑、删除权限仅作者本人可操作。
6. 小说分类只能从已有分类中选择，不允许在小说创建、上传或编辑时输入新分类。
7. 分类的新增、重命名、删除只允许管理员操作。
8. 修复搜索无结果导致页面异常无渲染的问题，并补充回归测试。

## 非目标

- 不做完整作者工作台、草稿箱、审核流或发布状态机。
- 不做富文本编辑器，章节内容仍使用纯文本。
- 不做用户改用户名；用户名作为登录名和作者引用名保持不可变。
- 不做找回密码、邮箱/手机号绑定或第三方登录。
- 不做用户头像、个人主页、关注、收藏、书架、评论、打赏或付费章节。
- 不做分类层级、分类排序和复杂分类推荐。
- 不做软删除或回收站，删除策略沿用当前硬删除。

## 默认实现假设

- `users.username` 是作者引用展示名，用户设置的昵称不影响小说作者展示。
- `users.nickname` 新增字段，注册时默认写入用户名。
- 修改密码需要提供当前密码和新密码。
- `books.owner_user_id` 新增字段，引用上传或创建小说的系统用户。
- `books.author` 字段进入兼容期：迁移时用来回填历史数据，API 对外继续返回 `author`，但返回值由 `owner_user_id` 关联用户动态计算；后续可再移除旧字段。
- 管理员创建或上传的小说仍记录 `owner_user_id = 管理员用户 ID`，但 API 统一展示 `author = "系统"`。
- 普通用户上传或创建小说时，后端忽略前端传入的作者字段，作者由登录用户决定。
- 管理员可以管理所有小说和章节；普通用户只能管理 `owner_user_id` 等于自己的小说和章节。
- 小说创建、上传和编辑时只接受 `categoryId`，不接受自由文本 `category` 创建分类。
- 如果分类被书籍使用，默认不允许删除，返回 `CONFLICT`。

## 契约变化

### API

#### 账号资料

新增：

- `PATCH /api/auth/me`
  - 认证：需要登录。
  - 请求：`{ "nickname": "新的昵称" }`
  - 响应：当前用户，包含 `id`、`username`、`nickname`、`role`。

- `PATCH /api/auth/password`
  - 认证：需要登录。
  - 请求：`{ "oldPassword": "old", "newPassword": "new" }`
  - 响应：`{ "changed": true }`
  - 错误：当前密码错误返回 `UNAUTHORIZED` 或 `BAD_REQUEST`，新密码不合规则返回 `BAD_REQUEST`。

修改：

- `POST /api/auth/register`
  - 注册成功时 `nickname` 默认为 `username`。
  - 响应增加 `nickname`。

- `POST /api/auth/login` 和 `GET /api/auth/me`
  - `user` 增加 `nickname`。

#### 分类

保留：

- `GET /api/categories`
  - 公开可读，用于搜索筛选和小说表单选择。

新增管理员分类管理：

- `POST /api/admin/categories`
  - 认证：需要管理员角色。
  - 请求：`{ "name": "武侠" }`
  - 响应：分类对象。

- `PATCH /api/admin/categories/{categoryId}`
  - 认证：需要管理员角色。
  - 请求：`{ "name": "新分类名" }`
  - 响应：分类对象。

- `DELETE /api/admin/categories/{categoryId}`
  - 认证：需要管理员角色。
  - 响应：`{ "deleted": true }`
  - 如果分类已被书籍使用，返回 `CONFLICT`。

#### 作品创建和上传

新增登录用户作品接口：

- `GET /api/me/books`
  - 认证：需要登录。
  - 普通用户只返回自己的作品；管理员可继续使用 `/api/admin/books` 查看全部。
  - 查询参数同搜索：`q`、`categoryId`、`page`、`pageSize`。

- `POST /api/me/books`
  - 认证：需要登录。
  - 用于新建空小说。
  - 请求：`{ "title": "书名", "categoryId": 1, "description": "简介" }`
  - 响应：书籍对象，`author` 由后端根据登录用户计算。

- `POST /api/me/books/upload`
  - 认证：需要登录。
  - 用于普通用户或管理员上传 `.txt`。
  - 内容类型：`multipart/form-data`
  - 字段：`title`、`categoryId`、`description`、`file`
  - 不再接收 `author` 自由文本。

兼容或调整管理员接口：

- `POST /api/admin/books/upload`
  - 保留兼容，但请求字段改为 `categoryId`，不再创建分类。
  - 管理员上传的书籍展示作者为“系统”。

- `POST /api/admin/books`
  - 新增管理员新建空小说。
  - 请求同 `POST /api/me/books`，作者展示为“系统”。

#### 作品编辑和章节管理

新增或调整：

- `PATCH /api/books/{bookId}`
  - 认证：需要登录。
  - 权限：管理员或作者本人。
  - 请求：`{ "title": "书名", "categoryId": 1, "description": "简介" }`
  - 不允许修改作者。

- `DELETE /api/books/{bookId}`
  - 认证：需要登录。
  - 权限：管理员或作者本人。

- `POST /api/books/{bookId}/chapters`
- `PATCH /api/books/{bookId}/chapters/{chapterId}`
- `DELETE /api/books/{bookId}/chapters/{chapterId}`
  - 认证：需要登录。
  - 权限：管理员或作者本人。
  - 章节追加、编辑、删除规则沿用 Phase 4。

兼容策略：

- 现有 `/api/admin/books/{bookId}` 和 `/api/admin/books/{bookId}/chapters...` 可保留为管理员专用别名，内部复用同一服务和权限逻辑。

#### 搜索

确认并加固：

- `GET /api/books/search` 在无结果时必须稳定返回：

```json
{
  "items": [],
  "total": 0
}
```

前端必须渲染空状态，不允许白屏或异常中断。

### 数据

新增字段：

- `users.nickname VARCHAR(64) NOT NULL DEFAULT ''`
- `books.owner_user_id BIGINT NULL`

新增索引和约束：

- `books.owner_user_id` 外键引用 `users(id)`。
- `idx_books_owner_user_id (owner_user_id)`。

迁移规则：

- 给已有用户补齐 `nickname = username`。
- 给已有书籍回填 `owner_user_id`：
  - 如果旧 `books.author` 能匹配某个 `users.username`，则绑定该用户。
  - 如果不能匹配，绑定管理员账号，并在 API 中展示作者为“系统”。
- `books.author` 在本阶段不立即删除，避免一次性迁移风险；服务层和 API 不再把它作为真实作者来源。

分类规则：

- 小说创建、上传、编辑时只接受已有 `categoryId`。
- 如果 `categoryId` 不存在，返回 `BAD_REQUEST` 或 `NOT_FOUND`，不自动创建分类。
- 分类新增、重命名、删除只允许管理员接口。

### UI 状态

新增或调整页面：

- 账号设置页：
  - 展示用户名、昵称、角色。
  - 支持修改昵称。
  - 支持修改密码。
  - 覆盖加载、保存中、成功、错误、当前密码错误状态。

- 作品管理页：
  - 登录用户可访问。
  - 普通用户只看到自己的小说。
  - 管理员可从后台看到全部小说。
  - 支持新建小说、上传小说、编辑小说、删除小说、章节新增/编辑/删除。
  - 作者字段只展示，不可编辑。
  - 分类使用下拉选择，不使用自由输入。

- 管理员分类管理：
  - 展示分类列表。
  - 支持新增、重命名、删除。
  - 分类被书籍使用时展示不可删除或删除失败提示。

- 搜索结果页：
  - 无结果时展示稳定空状态。
  - 搜索接口返回空数组、缺省数组或异常时都不能导致页面白屏。

## 验收标准

- 注册用户注册后 `nickname` 默认为 `username`。
- 登录用户可以修改昵称。
- 登录用户可以通过旧密码修改新密码；旧密码错误时修改失败。
- 管理页面支持新建空小说。
- 普通用户可以上传小说，上传后的作者展示为该用户的 `username`。
- 管理员上传或新建小说，作者展示为“系统”。
- 普通用户只能编辑、删除自己创建或上传的小说和章节。
- 普通用户不能编辑、删除他人的小说和章节。
- 管理员可以编辑、删除所有小说和章节。
- 小说创建、上传和编辑表单使用分类下拉选择，不允许自由输入分类并自动创建。
- 分类新增、重命名、删除仅管理员可操作。
- 搜索无结果时页面稳定渲染空状态，不出现白屏或异常。
- `make test` 通过。
- `npm run build` 通过。
- `make docker-build` 通过。
- `make smoke` 通过或记录未覆盖项。
