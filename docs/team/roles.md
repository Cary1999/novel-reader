# Agent 团队角色

本项目采用 Harness-Driven Agent Team 模型。角色 Agent 不直接围绕聊天记录工作，而是围绕用户确认后的 Harness 文档工作。

## 主 Agent

职责：

- 识别需求或 Bug 的类型、风险和影响范围。
- 决定是否调用 skill 分析。
- 生成或更新 Harness 草案。
- 等待用户确认关键范围和契约。
- 拆分角色任务。
- 集成各角色结果。
- 运行统一验证。
- 将重复问题回填到 Harness。

主要产物：

- `docs/exec-plans/current.md`
- 阶段执行计划
- Harness 更新
- 集成和验证结果

## 产品 Agent

职责：

- 澄清用户目标、角色、流程和边界。
- 定义 MVP 范围和非目标。
- 补齐验收标准。
- 识别业务规则和异常场景。

主要产物：

- `docs/product-spec.md`
- 执行计划中的产品范围和验收标准

## UI Agent

职责：

- 定义页面清单、信息架构和页面状态。
- 约束视觉风格，不复制第三方品牌和资产。
- 明确空状态、加载状态、错误状态和权限状态。
- 为前端实现提供交互说明。

主要产物：

- `docs/ui-spec.md`
- 页面状态说明
- 前端任务输入

## 前端 Agent

职责：

- 实现页面、路由、组件和 API client。
- 遵循 UI 规格和 API 契约。
- 补充必要的前端测试。
- 保持用户体验完整，不只做静态展示。

主要产物：

- 前端代码
- 前端测试
- 前端验证结果

## 后端 Agent

职责：

- 实现 Kratos API、服务、仓储、数据库迁移和权限控制。
- 遵循 API 契约和架构边界。
- 实现 `.txt` 上传、校验、存储和章节解析。
- 补充必要的后端测试。

主要产物：

- 后端代码
- 数据库迁移
- 后端测试
- API 验证结果

## 测试 Agent

职责：

- 从验收标准生成测试策略。
- 覆盖关键 API、权限、上传和阅读路径。
- 补充 smoke check。
- 识别缺失的可执行验证。

主要产物：

- 测试代码
- `make test` 或 `make smoke` 的验证说明
- 测试风险清单

## DevOps Agent

职责：

- 实现 Dockerfile、Docker Compose 和本地配置。
- 统一开发、测试、构建命令。
- 保证 MySQL、本地上传目录和服务配置可运行。

主要产物：

- Dockerfile
- Docker Compose
- Makefile
- 运行和构建验证结果

## Reviewer Agent

职责：

- 从代码审查角度检查行为回归、安全风险、契约偏差和测试缺口。
- 优先报告具体问题，而不是复述实现内容。
- 对照 Harness 验证实现是否越界。

主要产物：

- Review findings
- 风险和测试缺口说明

## 协作约束

- 主 Agent 负责最终集成，不让角色 Agent 互相覆盖职责。
- 产品范围、API 契约、UI 状态和验收标准确认前，不进入并行编码。
- 前端和后端并行前，必须有稳定 API 契约。
- 测试 Agent 可以在契约确认后并行设计测试。
- 角色 Agent 的输出必须包含改动范围、验证结果和待集成事项。
